# Mystic

[![CI](https://github.com/jagajith23/mystic/actions/workflows/ci.yml/badge.svg)](https://github.com/jagajith23/mystic/actions/workflows/ci.yml)

Mystic is a small, dynamically typed programming language with a hand-written
tree-walking interpreter, implemented twice: once in **Java** (`JMystic`) and
once in **Python** (`PMystic`). Both implementations run the same programs and
produce identical output.

```
fun makeCounter() {
  store i = 0;
  fun count() {
    i = i + 1;
    return i;
  }
  return count;
}

store next = makeCounter();
print next(); // 1
print next(); // 2
```

## Features

- Numbers, strings, booleans and `nil`
- Variables declared with `store`, with lexical block scoping
- `if` / `else`, `while`, `for`, plus `break` and `continue`
- The ternary operator: `age >= 18 ? "adult" : "minor"`
- First-class functions, recursion and closures
- String and number concatenation with `+`
- A native `clock()` function
- Errors that report their line: syntax errors, static errors (for example
  `break` outside a loop, or reading a variable in its own initializer) and
  runtime errors
- A REPL and a file runner

## How it works

Source code goes through four stages, each in its own file:

| Stage | What it does | Java | Python |
|---|---|---|---|
| Scanner | Turns characters into tokens | `Scanner.java` | `scanner.py` |
| Parser | Recursive descent, builds the syntax tree | `Parser.java` | `mystic_parser.py` |
| Resolver | Static pass that binds each variable to its scope, so closures capture the right one | `Resolver.java` | `resolver.py` |
| Interpreter | Walks the tree and evaluates it | `Interpreter.java` | `mystic_interpreter.py` |

The syntax tree classes (`Expr`, `Stmt`) are generated by a small script in
each implementation's `tools/` folder.

## Running it

Python (tested with 3.9 and 3.12):

```bash
python3 PMystic/mystic/mystic.py examples/fibonacci.my   # run a file
python3 PMystic/mystic/mystic.py                         # start the REPL
```

Java (tested with JDK 21):

```bash
javac -d build JMystic/mystic/*.java
java -cp build JMystic.mystic.Mystic examples/fibonacci.my
java -cp build JMystic.mystic.Mystic                     # start the REPL
```

## Examples

The [`examples/`](examples) folder has one short program per feature, each with
its expected output next to it:

| Program | Shows |
|---|---|
| [`closures.my`](examples/closures.my) | Functions capturing their defining scope |
| [`fibonacci.my`](examples/fibonacci.my) | Recursion and `for` loops |
| [`scope.my`](examples/scope.my) | Block scoping and shadowing |
| [`loops.my`](examples/loops.my) | `break` and `continue` |
| [`ternary.my`](examples/ternary.my) | The ternary operator and equality |
| [`errors.my`](examples/errors.my) | A runtime error with its line number |
| [`static_errors.my`](examples/static_errors.my) | Mistakes caught before the program runs |

## Tests

The test runner executes every example and compares the output with its `.out`
file. CI runs it against both interpreters on every push.

```bash
python3 tests/run_examples.py              # Python interpreter
python3 tests/run_examples.py --impl all   # Python and Java (needs a JDK)
```

## Background

I built Mystic while working through Robert Nystrom's
[Crafting Interpreters](https://craftinginterpreters.com/), following the
design of its Lox language. On top of that base I added:

- `break` and `continue`, checked statically so they cannot appear outside a loop
- the ternary operator
- string and number concatenation
- a division-by-zero runtime error
- a complete second implementation in Python, written to understand how the
  same design maps onto a different language

Classes are not implemented yet; `class`, `this` and `parent` are reserved
words for that work.
